💡 Ce sunt tabelele?

Gândește-te la baza de date ca la un fisier Excel cu mai multe foi (sheet-uri). Fiecare "foaie" se numește tabel și stochează date despre un singur lucru. De exemplu: tabelul stores conține doar informații despre magazine.


Rândurile = recorduri individuale (ex: un magazin anume)
Coloanele = tipuri de informații (ex: nume magazin, adresă, etc.)

📊 Tabele Reporting (Date Agregate)

📊 Ce înseamnă "Reporting" sau "Agregate"?

Aceste tabele conțin date pre-calculate (agregate) din tranzacțiile brute. Nu sunt date introduse manual - sunt calculate automat pentru a face aplicația rapidă.


Exemplu: În loc să numărăm 10.000 de tranzacții pentru a afla vânzările din Martie, tabelul reporting_agent_month already conține aceste numere calculate.

🔗 Cum se leagă tabelele între ele (Relații)

sales_transactions → stores Fiecare tranzacție aparține unui magazin (site_code)
sales_transactions → import_snapshots Tranzacțiile sunt grupate pe importuri (snapshot_id)
visits → stores Fiecare vizită este la un magazin (site_code)
tl_store_assignments → users TL-urile au magazine atribuite (user_id)
tl_store_assignments → stores Fiecare assignment e pentru un magazin (site_code)
focus_products → users Produsele focus sunt adăugate de un user (added_by)
salary_records → stores Salariile pot fi legate de un magazin (site_code)
store_targets → stores Targeturile sunt pe magazin (site_code)
import_snapshots → users Importurile sunt făcute de un user (imported_by)

📊 Fluxul Datelor

1. Import → Se încarcă fișiere CSV cu tranzacții → ajung în sales_transactions
2. Processing → Datele brute sunt agregate → ajung în tabelele reporting_*
3. Afișare → Aplicația citește din tabelele reporting (rapid) nu din tranzacții (lent)
4. Vizite → Agenții completează rapoarte de vizită → ajung în visits
5. Salarii → Date importate din SQLite → ajung în salary_records
