# H-12 — Spreadsheet formula neutralization

## Revalidated risk

Untrusted text is written into OpenPyXL workbooks through generic `append()` paths. OpenPyXL interprets strings beginning with `=` as formulas, and spreadsheet applications also treat additional prefixes as potentially active when opening XLSX/CSV content. The application also contains intentional, application-owned formulas in the Grile salary workbook, so a blanket conversion of every formula-looking string would break required calculations.

## Security boundary

Values originating from imports, PostgreSQL, Google Sheets, user-entered notes, names, locations, product descriptions, filenames or API payloads are **untrusted text**.

Formulas are allowed only when created explicitly by application code through a typed trusted-formula marker. A raw string beginning with a formula prefix is never considered trusted merely because it comes from an internal database.

## Dangerous text prefixes

After preserving the original string exactly for display, treat text as formula-capable when its first character is one of:

```text
= + - @ TAB CR LF
```

Numeric Python values (`int`, `float`, `Decimal`) remain numeric. Date/time and boolean values retain their native types. A textual value such as `"-12"` remains untrusted text and is neutralized; callers that require a number must parse and validate it before the writer boundary.

## Target API

Create one central module, for example:

```text
backend/services/spreadsheet_safety.py
```

Recommended public contract:

```python
@dataclass(frozen=True)
class TrustedFormula:
    expression: str


def spreadsheet_cell_value(value: object) -> object:
    """Return a safe value for XLSX/CSV/Sheets writers."""


def set_openpyxl_cell(cell: Cell, value: object) -> None:
    """Write native values, trusted formulas, or explicitly safe text."""


def csv_cell_value(value: object) -> object:
    """Return a neutralized CSV field while preserving native numbers."""


def google_sheets_value(value: object) -> object:
    """Return an untrusted value suitable for RAW writes."""
```

Equivalent names are acceptable, but there must be one source of truth.

## XLSX rules

- Untrusted formula-looking strings must be stored as text, not OpenPyXL `data_type='f'`.
- Prefixing with an apostrophe is acceptable when tests demonstrate the workbook reopens as text and not as a formula.
- Prefer a dedicated cell writer that sets the value and text type explicitly rather than relying on every call site to remember the rule.
- Trusted formulas use `TrustedFormula` and are validated to begin with `=`.
- No DB/import/user string may be wrapped as `TrustedFormula`.
- Existing number formats, styles, hyperlinks and chart references must remain unchanged.

## CSV rules

- Sanitize each field before `csv.writer`/`DictWriter` receives it.
- Native numeric values remain numeric.
- Formula-looking strings are neutralized even when quoted by the CSV library; quoting alone is not a security control.
- Preserve delimiter, encoding and newline behavior.

## Google Sheets rules

- Untrusted writes must use `valueInputOption='RAW'` wherever possible.
- `USER_ENTERED` is allowed only for a deliberately separated trusted-formula path.
- Never mix untrusted user/import values and trusted formulas in an undifferentiated `USER_ENTERED` payload.
- Read-only Google operations and exported remote XLSX files are outside the writer transformation; do not mutate source sheets during this finding.

## Known high-risk surfaces

The implementation inventory must include, but not be limited to:

- generic reports in `backend/services/exports.py`;
- Target Calculator workbook export;
- Grile final salary workbook and Audit sheet;
- any salary, campaign, incentive, forecast or visits export;
- every `Workbook`, `write_only`, `ws.append`, direct cell assignment and `save` path;
- every CSV writer;
- every Google Sheets `values().update`, `append`, `batchUpdate` or equivalent write;
- scripts/routers that generate downloadable spreadsheet content.

The Grile formulas for total salary and cash salary are trusted application formulas and must continue to calculate. Names, stores, managers, sheet IDs, errors and metadata in the same workbook remain untrusted text.

## Required regression payloads

At minimum test:

```text
=HYPERLINK("https://example.invalid","click")
=1+1
+SUM(1,1)
-1+2
@SUM(1,1)
\t=1+1
\r=1+1
\n=1+1
```

Also test:

- normal text;
- empty string and `None`;
- native positive/negative integers, floats and `Decimal`;
- a textual negative number (`"-123"`);
- non-ASCII Romanian text;
- trusted formulas generated by application code;
- round-trip workbook reload with `data_only=False` and direct inspection of `cell.data_type`.

## Inventory and enforcement

Before modification, create an inventory with `rg` for OpenPyXL, CSV and Sheets writer APIs. After modification, repeat it and justify every remaining raw writer. Generic raw `ws.append([...untrusted...])` paths must not remain.

A focused static regression test may inspect known writer modules or centralize writer usage so future export code cannot bypass the safety layer silently.

## Acceptance criteria

- Every server-side XLSX/CSV/Google Sheets writer is inventoried.
- All untrusted formula-capable text remains text after round-trip.
- Intentional Grile formulas remain formulas and retain their exact expressions.
- Native negative numbers remain numbers.
- No UI/API/export schema changes are introduced beyond neutralization.
- Full mypy and isolated PostgreSQL test suites pass.
- No production files, Google Sheets or databases are modified during implementation.

## Rollback

Revert the H-12 implementation commit. No schema or data rollback is required. Generated test workbooks remain ephemeral and must not be committed.

## Production verification

After the approved Wave 1 deployment, generate controlled reports containing synthetic harmless formula-prefix values in a non-production fixture or approved test scope. Open the generated workbooks in a protected environment and confirm that untrusted cells are text while application-owned formulas still calculate. Do not use command/DDE payloads against employee workstations.
