## Exact AI contract (AC-02, AC-03, AC-14)

- Request: unique nonempty `series_ids`; horizon `1..12`; input count equals ID
  count; each context finite/nonnegative; covariate outer/inner cardinalities
  match series and `context+horizon`.
- Response profile is mandatory: `point_only_v1` forbids
  `quantile_forecast`; `point_quantiles_v1` requires exactly `horizon` quantile
  rows, each using the documented TimesFM 9- or 10-value layout from which
  q10/q20/q50/q80/q90 are selected and ordered. In both profiles `series` is a
  list with exact unique request IDs and every `point_forecast` has exactly
  `horizon` entries. A missing quantile fails only the quantile profile;
  undeclared quantiles fail the point-only profile. Unknown/duplicate IDs,
  short/extra points, invalid layouts, NaN/Infinity and negative values always
  fail closed.
- `sales_value` model output is quantized half-up to `0.01`. Continuous model
  output for `units` is intentionally allowed, quantized half-up once, and
  records raw/quantized response hashes plus precision-loss count; the CSV
  importer accepts only already-integral nonnegative unit values and never
  silently rounds. This preserves the existing forecasting meaning while
  making the boundary explicit.
- Coverage modes are explicit CLI choices: `fail_closed` (default) or
  `seasonal_fallback`. Only missing series/pairs or an explicitly handled
  timeout may fallback; malformed/unknown/nonfinite responses never do.
  Fallback is keyed by exact pair. Import never invents fallback and requires
  100% expected cohort pairs, unique known stores, one source month per target,
  required anchor for rolling-12, cohort/response hashes and counts.
- Adversarial tests: empty response, missing/duplicate/unknown series,
  short/long horizon, missing/reordered quantiles, NaN, ±Infinity, negative,
  timeout, missing source/anchor, duplicate CSV pair, unknown store and distinct
  monthly fallback.
- Migration 069 adds immutable `ai_forecast_cohort_snapshots` and rows with
  `site_code,source_month,is_operating,firma,regional,asm,authority_source,
  confidence,source_generation`. Candidate stores are those whose observational
  interval (`first_seen_month..last_seen_month`) intersects the source month;

  zero. Organisation comes only from one unambiguous

  source, never current `stores`. Any unknown/ambiguous field makes the window
  decision `BLOCKED` while still emitting sanitized coverage diagnostics.
- Required temporal fixtures are: `opened_after_cutoff`,
  `closed_after_cutoff`, `zero_sales_with_official_target`,

## Transactional outbox contract (AC-12)

Event names and producers:

- `retail.sales_generation_promoted.v1` — sales promotion transaction;
- `retail.pnl_generation_promoted.v1` — protected P&L promotion transaction;
- `retail.salary_import_completed.v1` — protected salary import transaction;
- `retail.planning_forecast_promoted.v1` — Planning head CAS transaction;
- `retail.grile_manifest_approved.v1` — Grile approval transaction.

Payload contains only event schema, aggregate type/opaque ID, generation/source
hash, cutoff/month, revision and timestamps; no CNP, person/name, salary amount,
raw business row or credential. Unique key is
`event_type:aggregate_id:generation_hash:revision`. Within each producer the
event insert is in the same PostgreSQL transaction. The existing operations
worker owns dispatch; no new service identity or queue is created.

State is `pending|processing|completed|dead`; every producer allocates a
monotonic `aggregate_sequence` in the producer transaction and the database
enforces uniqueness on
`(aggregate_type,aggregate_id,aggregate_sequence)`. Claim uses `FOR UPDATE SKIP
LOCKED`, aggregate advisory lock, 60-second lease, owner token and epoch. A row
is claimable only when every lower sequence for that aggregate is `completed`;
an earlier pending, processing or dead row blocks later delivery and exposes a
finite `head_blocked` metric. Schedule after failures is
5/30/120/300/900/1800/3600/3600 seconds; attempt 8 becomes `dead`.

Transport is explicitly at-least-once. Consumers use
`(event_id,consumer)` unique receipts plus a domain generation/idempotency key;
crash-before-effect, crash-after-effect-before-ack and duplicate dispatch may
repeat transport but must result in one effective domain mutation. Sales
consumer replaces the current post-commit Campaigns→single Grile V2 request
chain; the Grile handler may be delivered repeatedly but a claimed sales
generation produces exactly one effective fenced Sheets mutation. The other
four consumers initially write the auditable delivery receipt only until their
already-protected live apply is separately authorized. This avoids inventing
business side effects.

Replay is an admin-only CLI using the operations DB authority, exact event ID
and nonempty bounded reason; only `dead` events may requeue and replay is itself
append-only audited. Metrics have only finite event-type/state labels: pending
age, head-blocked age/count, completed/failed counters and duration. Synthetic
steady-state gates are p95 event-created-to-completed `<30 s`, oldest pending
`<60 s`, one-hour failed-attempt ratio `<1%`, and dead count exactly `0`.
Tests inject commit loss, Valkey down, worker crash before/after effect, lease
expiry, duplicate delivery, ordering collision, poison event/DLQ and replay.
Protected producer paths are tested only in isolated databases; no live
Finance/salary/Planning/Grile promotion is invoked. Old artifacts see only
additive unused schema.

## Integrated and runtime proof

Release A is built from one clean SHA containing only contract/docs/tooling plus
additive migration 069 relative to the baseline application. Local proof starts
from an empty disposable DB and from a restored sanitized pre-069 DB, applies
069, verifies schema hashes/constraints and runs the unchanged baseline app
against it. Only then: PR-A CI, merge, exact-main-A CI, immutable artifact and
digest verification, and a fresh independent schema/compatibility audit. Deploy
A creates a root-protected backup, applies 069, installs exact artifact A and
proves health/schema/outbox-empty. A is the rollback target for B.

Release B is branched from exact main A and must not add/change/remove any
migration. Integrated checks run once, sequentially, against one unchanged B
SHA: vendored package integrity; isolated backend suite; mypy; OpenAPI
generation/diff; Python and TS complexity; targeted mutation; frontend
coverage; typecheck; lint; dependency/security/secret/migration/docs/systemd/
Prometheus gates; build; browser/PWA; load/query plans and isolated restore.
A failed check is rerun only after a relevant content/environment correction.
A fresh auditor first checks this local SHA. Then PR-B CI, merge and exact-main-B
CI produce the immutable B artifact; no deployment occurs yet.

The final pre-deploy auditor receives the unpacked exact-main-B artifact,
artifact digest/provenance, contract lock and Release-A artifact. It reruns
AC-01..AC-16 from the artifact and performs a sandbox install A→B→A. Both
artifacts must have byte-identical migration manifests through 069, and A after
rollback must return `/readyz` 200 with the additive data/schema intact. Only a
`PASS` authorizes deployment of B.

Before each deploy: exact-main artifact `SOURCE_SHA`, `SHA256SUMS`, SBOM,
provenance, Sigstore identity and migration manifest verify; fresh
root-protected backup handle exists; `pg_restore --list` succeeds. Deploy B
must report its backup and exact-A rollback handle; automatic rollback installs
A, never the pre-069 artifact and never down-migrates production.

Post-deploy exact gates:

1. primary checkout, GitHub `main`, artifact `SOURCE_SHA`, runtime-release
   directory and every systemd fragment symlink equal the same 40-char SHA;
2. schema ledger contains 069 with the manifest checksum and zero pending/
   failed migration; outbox starts with zero unintended live events;
3. backend plus operations/import/Grile/export/salary-export workers are
   `active`, no unexpected restart, and local `/livez`, local/public `/readyz`
   return 200 three times over a 120-second observation;
4. authenticated manager probes: Dashboard read, Target read-only scenario
   listing, salary page read (no export), Grile V2 GET and settings views;
   forbidden-role salary probe stays 403. Grile snapshot is 21/21 and no Google
   GET is emitted;
5. Prometheus targets/rules are green, finite outbox metrics exist, and journal
   since deploy has zero new traceback/critical and zero repeated warning class
   (`>=3` identical normalized warnings). GlitchTip recent events stay zero or
   are individually reconciled to the release probe;
6. no open task PR/worktree/branch and Dell/server/GitHub refs for this
   objective are clean/equal. Pre-existing unrelated refs/worktrees are only
   reported; this objective does not delete them.

A fresh post-deploy auditor receives only the contract, exact deployed
artifact/SHA and evidence locations. It returns strict
`VERDICT: PASS|FAIL|BLOCKED` for AC-17.
The primary agent records the verdict and moves this file to
`docs/exec-plans/completed/` only on `PASS`.

## Rollback/recovery

- No fallback calls the defective Target solver.
- Invalid AI remains an unpromoted candidate; previous Planning head is
  untouched.
- Outbox failure retains the already-committed good generation and is replayed
  idempotently; it never converts missing data into zero.
- Grile failure retains the prior atomic snapshot; no destructive operation is
  introduced.
- Additive 069 remains inert under Release A. Release B has the byte-identical
  migration manifest, so runtime rollback installs the exact signed A artifact
  without a schema downgrade. A pre-069 artifact is correctly refused.
  Production DB restore requires a separate owner decision and is not performed
  by this objective.
