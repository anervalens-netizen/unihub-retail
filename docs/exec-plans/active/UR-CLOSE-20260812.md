# UniHub Retail definitive closure

Status: IN PROGRESS

Owner exception: salary export is explicitly out of scope.

Delivery rule: ADR-006 exact-SHA artifact and formal deploy only.

## Outcome

Close the demonstrated Retail defects without turning release evidence into a
second product. The implementation already exists. Remaining work is to prove
the schema transition, run normal regression checks, deliver the signed
artifact, and verify the repaired paths in production.

## Safety fences

- No salary export, salary apply, finance apply, Target finalization, Grile
  reset, or destructive data operation.
- Migration 069 is additive. Release A must leave the transactional outbox
  empty and must remain a valid rollback floor for Release B.
- Production changes use a PR, successful CI for the exact main SHA, a signed
  immutable artifact, the formal deployer, backup, and automatic rollback.
- Evidence contains hashes, counts, statuses, and timings only; never CNP,
  salary values, names, cookies, or raw business rows.
- Shared Caddy, Tunnel, Authentik, and network configuration are outside this
  release.

## Acceptance contract

### A. Schema 069 compatibility — UNVERIFIED

- An empty database migrates through 069 and starts the Release-A runtime.
- A sanitized schema at 068 restores, migrates through 069, and starts the
  same runtime.
- Both paths produce the same migration ledger and schema catalog.
- Migration 069 and the manifest agree; `retail_outbox_events` remains empty.

Evidence: `scripts/run_release_a_schema_gate.sh`, its JSON result, and the two
six-test JUnit reports generated by exact-main CI.

### B. Repaired business paths — UNVERIFIED

- Sales retained artifacts preserve cross-identity ownership and retry safely.
- Sales promotion and its outbox event commit in the same transaction.
- Promo generations own and hash their rule masters; v1 and unowned-v2
  migration is atomic, idempotent, and fail-closed.
- Outbox delivery renews leases, fences stale owners, writes fresh timestamps,
  and is effective-once.
- Campaign/Grile delivery binds generation hash and sales revision. A
  superseded generation is a terminal no-op; the current generation produces
  one effect.

Evidence: the focused incident tests plus the ordinary backend regression
suite. No synthetic 10,000-event or 2x/5x scale benchmark is required.

### C. Standard quality — UNVERIFIED

- Backend tests and coverage pass.
- Backend type checking, security checks, migration manifest checks, and
  deployment sandbox pass.
- Frontend typecheck, lint, tests, build, browser smoke, and integration E2E
  pass.
- A fresh independent auditor finds no P0/P1 in the exact candidate.

Evidence: one PR CI run and one exact-main release CI run. Unchanged checks are
not replayed locally or in extra workflows.

### D. Formal delivery — UNVERIFIED

- CI packages the exact main Git tree and tested frontend build.
- `SOURCE_SHA`, `SHA256SUMS`, manifest, SBOM/provenance, and Sigstore identity
  bind the artifact to the successful workflow run.
- The deploy workflow accepts only that successful main run and invokes the
  root-owned formal deployer under the global lock.
- Backup and automatic rollback remain available; Release B preserves the
  migration manifest established by Release A.

Evidence: main run ID/SHA, artifact digest/signature verification, deploy run,
and rollback handle.

### E. Production proof — UNVERIFIED

- Deployed checkout/runtime equals the released SHA and is clean.
- Migration ledger contains exact 069; outbox has no dead/stale work.
- Backend and workers are active; local/public health and readiness pass.
- Authenticated read-only probes cover Grile V2 (21 stores), the salary page
  without export, and the changed sales/promo status surfaces.
- Promo pointer and rule-master hashes are self-contained; retained sales
  artifact metadata/path/digest/mode are consistent.
- Relevant journals contain no new error burst.
- Independent final auditor accepts the exact artifact and live evidence.

## Execution

1. Finalize this lean release candidate and run focused local syntax/tests.
2. Run one independent pre-release audit.
3. Push the single candidate PR and require normal CI success.
4. Merge, dispatch exact-main CI, verify its signed artifact, and deploy.
5. Run the read-only production proof and independent final audit.

Release A and Release B remain the two requested delivery boundaries, but use
the same short evidence model. A real failure stops deploy and is fixed once;
absence of an artificial evidence field does not.

## Removed non-requirements

The following are intentionally not acceptance gates: recursive per-file
authority inventories, preview/tag topology counts, historical PR parent
reconciliation, exhaustive branch/worktree cleanup, empty complexity-ratchet
maps, fixed 10,000-event workloads, 2x/5x scale profiles, fixed 120-second
observation, duplicated full local/CI suites, and full desktop/mobile journeys
unrelated to the repaired paths.
