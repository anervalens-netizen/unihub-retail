## Exact AI contract (AC-02, AC-03, AC-14)

- Request: unique nonempty `series_ids`; horizon `1..12`; input count equals ID
  count; each context finite/nonnegative; covariate outer/inner cardinalities
  match series and `context+horizon`.
- Response profile is mandatory: `point_only_v1` forbids
  `quantile_forecast`; `point_quantiles_v1` requires exactly `horizon` quantile
  rows. A 9-value row maps zero-based indexes
  `q10=0,q20=1,q50=4,q80=7,q90=8`; a 10-value row maps
  `q10=1,q20=2,q50=5,q80=8,q90=9`, with index 0 ignored as the service's
  point/mean slot because `point_forecast` is authoritative. No other length is
  valid. Selected values must satisfy `q10<=q20<=q50<=q80<=q90`. In both
  profiles `series` is a list with exact unique request IDs and every
  `point_forecast` has exactly `horizon` entries. A missing quantile fails only
  the quantile profile; undeclared quantiles fail the point-only profile.
  Unknown/duplicate IDs, short/extra points, invalid layouts, NaN/Infinity and
  negative values always fail closed.
- `sales_value` model output is quantized half-up to `0.01`. Continuous model
  output for `units` is intentionally allowed, quantized half-up once, and
  records raw/quantized response hashes plus precision-loss count; the CSV
  importer accepts only already-integral nonnegative unit values and never
  silently rounds. This preserves the existing forecasting meaning while
  making the boundary explicit.
- Coverage modes are explicit CLI choices: `fail_closed` (default) or
  `seasonal_fallback`. Only missing series/pairs or an explicitly handled
  timeout may fallback; malformed/unknown/nonfinite responses never do.
  Fallback is keyed by exact pair. Import never invents fallback and requires
  100% expected cohort pairs, unique known stores, one source month per target,
  required anchor for rolling-12, cohort/response hashes and counts.
- Adversarial tests: empty response, missing/duplicate/unknown series,
  short/long horizon, missing/reordered quantiles, NaN, ±Infinity, negative,
  timeout, missing source/anchor, duplicate CSV pair, unknown store and distinct
  monthly fallback.
- Migration 069 adds immutable `ai_forecast_cohort_snapshots` and rows with
  `site_code,source_month,is_operating,firma,regional,asm,authority_source,
  confidence,source_generation`. Candidate stores are those whose observational
  interval (`first_seen_month..last_seen_month`) intersects the source month;
  that interval may identify an `unknown` but never proves operating. Operating
  authority is, in priority order: an explicit activity event effective by the
  cutoff, official `store_targets` for the source month, or a source-month
  reporting row. A missing contemporaneous signal is `unknown`, never closed or
  zero. Organisation comes only from one unambiguous
  `store_org_assignments` interval covering the source month; firm comes from a
  source-month reporting row or a separately persisted contemporaneous cohort
  source, never current `stores`. Any unknown/ambiguous field makes the window
  decision `BLOCKED` while still emitting sanitized coverage diagnostics.
- Required temporal fixtures are: `opened_after_cutoff`,
  `closed_after_cutoff`, `zero_sales_with_official_target`,
  `missing_operating_authority`, and `current_org_differs_from_as_of`. Each
  asserts cohort membership/status and current-master non-use. A sixth fixture
  runs old current-cohort and new as-of methods on the same synthetic history
  and freezes the expected membership and metric delta.
- Evaluation windows: last closed 3, 6 and 12 target months when available;
  eligibility needs at least 6 consecutive months and 12 months context per
  series. Gates: 100% pair coverage, zero invalids, fallback `<=5%`, overall
  absolute bias `<=10%`, no month absolute bias `>15%`, overall WAPE at least
  2% relatively better than best deterministic baseline, no region WAPE worse
  than baseline by more than 10 percentage points, feature PSI `<0.20`, source
  freshness no more than one closed month behind. Missing 6-month authority is
  `BLOCKED`, not promotion-eligible.
- Statistical eligibility uses the same covered store-month pairs for candidate
  and every baseline; zero-actual pairs remain present. For any set `S`,
  `WAPE(S)=sum(abs(forecast-actual))/sum(actual)` and
  `bias(S)=sum(forecast-actual)/sum(actual)`, with nonnegative actuals. A zero
  denominator makes that decision `BLOCKED`; individual zero rows never use or
  contribute an undefined MAPE. The best baseline is the eligible baseline
  with the smallest whole-window WAPE, ties broken by fixed method name.
  Relative improvement is
  `(WAPE_baseline-WAPE_candidate)/WAPE_baseline`; a zero best-baseline WAPE
  requires candidate WAPE zero but cannot prove superiority and is `BLOCKED`.

  A deterministic paired cluster bootstrap uses each `site_code` as one
  resampling unit and includes all its eligible target months. With Python
  `random.Random(20260812)`, sample exactly the number of distinct stores with
  replacement for each of 10,000 replicates; candidate and baseline use the
  identical sampled clusters. Compute `delta=WAPE_candidate-WAPE_baseline`.
  A zero-denominator replicate is redrawn, consuming the same RNG stream, up to
  100 attempts; failure is `BLOCKED`. Sort all 10,000 deltas and use nearest-
  rank elements `ceil(0.025*N)-1` and `ceil(0.975*N)-1` as the 95% interval.
  Its upper bound must be `<0`, and candidate must have lower monthly WAPE in
  at least 5 of the same 6 consecutive monthly windows.

  Pinball is mandatory for governance eligibility, so a `point_only_v1` run may
  remain a valid unpromoted candidate/import but its governance decision is
  `BLOCKED` with reason `quantiles_required`. For
  `tau in {0.10,0.50,0.90}`, pair loss is
  `max(tau*(actual-q_tau),(tau-1)*(actual-q_tau))`. Window normalized pinball
  is `sum(pair_loss)/sum(actual)` on the identical cohort for each available
  last-closed 3-, 6- and 12-month window; zero denominator is `BLOCKED`.
  Deterministic baselines use their point forecast as a degenerate `q_tau` for
  all three taus. For each tau/window, candidate normalized pinball must be no
  more than `1.05` times the smallest eligible baseline value, ties by fixed
  method name; candidate quantile coverage must be 100%. Raw/normalized values,
  denominators and pair counts are evidence, and AC-03/AC-14 tests independently
  recompute them from frozen fixtures.

  `docs/contracts/ai-governance-golden-v1.json` is that independent fixture: two
  synthetic authoritative stores across the exact 12 closed months
  `2025-08..2026-07`, 24 pairs, one 9-value and one 10-value quantile layout,
  two deterministic baselines and exact 3/6/12 raw/normalized results. Frozen
  expectations include candidate WAPE/bias `0/0`, normalized candidate
  q10/q50/q90 pinball `0.005/0/0.005` in every window, best point-baseline WAPE
  `0.05`, bootstrap delta/CI `-0.05`, six of six wins, 100% quantile coverage
  and decision `eligible_candidate_only_no_live_promotion`. Tests expand the
  cartesian rows and recompute every expected value; runtime cannot rewrite the
  asset.

  Drift PSI is calculated for `log1p(monthly_value)`,
  `context_months` and `months_since_opening` using training-reference deciles,
  fixed epsilon `1e-6`, minimum 100 observations and threshold `<0.20` per
  feature. Categorical firm/manager share movement is reported and blocks when
  any absolute share delta exceeds 20 percentage points.

## Transactional outbox contract (AC-12)

Event names and producers:

- `retail.sales_generation_promoted.v1` — sales promotion transaction;
- `retail.pnl_generation_promoted.v1` — protected P&L promotion transaction;
- `retail.salary_import_completed.v1` — protected salary import transaction;
- `retail.planning_forecast_promoted.v1` — Planning head CAS transaction;
- `retail.grile_manifest_approved.v1` — Grile approval transaction.

Payload contains only event schema, aggregate type/opaque ID, generation/source
hash, cutoff/month, revision and timestamps; no CNP, person/name, salary amount,
raw business row or credential. Unique key is
`event_type:aggregate_id:generation_hash:revision`. Within each producer the
event insert is in the same PostgreSQL transaction. The existing operations
worker owns dispatch; no new service identity or queue is created.

State is `pending|processing|completed|dead`; every producer allocates a
monotonic `aggregate_sequence` in the producer transaction and the database
enforces uniqueness on
`(aggregate_type,aggregate_id,aggregate_sequence)`. Claim uses `FOR UPDATE SKIP
LOCKED`, aggregate advisory lock, 60-second lease, owner token and epoch. A row
is claimable only when every lower sequence for that aggregate is `completed`;
an earlier pending, processing or dead row blocks later delivery and exposes a
finite `head_blocked` metric. Schedule after failures is
5/30/120/300/900/1800/3600/3600 seconds; attempt 8 becomes `dead`.

Transport is explicitly at-least-once. Consumers use
`(event_id,consumer)` unique receipts plus a domain generation/idempotency key;
crash-before-effect, crash-after-effect-before-ack and duplicate dispatch may
repeat transport but must result in one effective domain mutation. Sales
consumer replaces the current post-commit Campaigns→single Grile V2 request
chain; the Grile handler may be delivered repeatedly but a claimed sales
generation produces exactly one effective fenced Sheets mutation. The other
four consumers initially write the auditable delivery receipt only until their
already-protected live apply is separately authorized. This avoids inventing
business side effects.

Replay is an admin-only CLI using the operations DB authority, exact event ID
and nonempty bounded reason; only `dead` events may requeue and replay is itself
append-only audited. Metrics have only finite event-type/state labels: pending
age, head-blocked age/count, completed/failed counters and duration. Synthetic
steady-state gates are p95 event-created-to-completed `<30 s`, oldest pending
`<60 s`, one-hour failed-attempt ratio `<1%`, and dead count exactly `0`.

The SLO harness uses seed `20260812` and a disposable PostgreSQL/Valkey pair.
Warmup is 500 successful events (100 per event type) at maximum feed rate; it
must drain, is recorded and is excluded from measurement. The measured run is
exactly 10,000 events: 2,000 per event type, 200 opaque aggregates per type and
10 ordered sequences per aggregate. Events arrive in sequence/type/aggregate
lexicographic order at a constant 20 events/second for 500 seconds. Four claim
loops each use batch size 50 and share eight handler slots; lease/retry values
remain those frozen above. Exactly every 200th measured event (50 total) gets
one deterministic transient first-attempt failure, then succeeds on its
5-second retry; no other measured fault is injected. Thus retries and
head-of-line behavior are exercised without a poison event in the SLO sample.

The harness drains for at most 60 seconds after the final arrival, samples
pending/head-blocked age once per second, and calculates latency from monotonic
enqueue/completion stamps. p95 is nearest rank
`sorted_latency[ceil(0.95*10000)-1]`. Failed-attempt ratio is
`failed_attempts/all_delivery_attempts` over the prior hour; while the measured
run is younger than one hour the window begins at its first event. It is
evaluated every five seconds after the first 200 attempts and must always stay
`<1%`; terminal counts must be 10,000 completed and zero pending/processing/
dead. All cardinalities, timings, attempts and percentile inputs are emitted.

Tests inject commit loss, Valkey down, worker crash before/after effect, lease
expiry, duplicate delivery, ordering collision, poison event/DLQ and replay.
Protected producer paths are tested only in isolated databases; no live
Finance/salary/Planning/Grile promotion is invoked. Old artifacts see only
additive unused schema.

## Rollback/recovery

- No fallback calls the defective Target solver.
- Invalid AI remains an unpromoted candidate; previous Planning head is
  untouched.
- Outbox failure retains the already-committed good generation and is replayed
  idempotently; it never converts missing data into zero.
- Grile failure retains the prior atomic snapshot; no destructive operation is
  introduced.
- Additive 069 remains inert under Release A. Release B has the byte-identical
  migration manifest, so runtime rollback installs the exact signed A artifact
  without a schema downgrade. A pre-069 artifact is correctly refused.
  Production DB restore requires a separate owner decision and is not performed
  by this objective.
