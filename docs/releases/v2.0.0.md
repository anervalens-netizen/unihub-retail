# UniHub Retail v2.0.0

> **Historical release note — not production authority.** This file preserves the release narrative recorded at that time. For machine-authoritative candidate/promotion identity and the derived-view procedure, see [`../README.md`](../README.md).

Release date: 2026-07-14

`v2.0.0` is the first formally versioned UniHub Retail release. At that historical date it identified the V2 operational baseline accepted on 2026-07-13 and reported as active in production. This release records the baseline; it does not introduce a new deployment, database migration or configuration change.

## Product highlights

- unified Hub analysis for current-month and historical Retail performance;
- canonical net quantity across Hub, Focus and KPI breakdowns, with returns
  still monitored separately;
- Management navigation for Manageri, Calculator Target, Salarii and P&L;
- current-year P&L default, company/store filtering and monthly/annual trends;
- agent evaluation, campaigns, promotions, incentives, visits, salaries,
  targets, imports, exports, AI Forecast and Retail-owned Grile workflows;
- responsive authenticated interface backed by Authentik OIDC.

## Security, privacy and correctness

- canonical return-receipt identity and safe monthly Grile transitions;
- formula neutralization for spreadsheet exports;
- opaque salary person identifiers and protected retained-CNP boundary;
- fail-closed typed OIDC configuration and bounded JWKS rotation/cache;
- server-side sessions, group-based privileged capabilities and distributed
  trusted-proxy-aware rate limiting;
- bounded/redacted DB error logging and immutable migration lifecycle;
- H-15 generated-artifact cleanup, governed rollback storage and rewritten
  controllable Git history, with the private PR-ref residual explicitly
  accepted by the business owner.

## Engineering and operations

- typed API contracts and domain boundaries for critical workflows;
- bounded Dashboard database fan-out and measured query-path improvements;
- strict TypeScript, lint, unit, isolated PostgreSQL, security, dependency,
  build, browser and accessibility CI gates;
- separate liveness/readiness probes, hardened systemd units, metrics, alerts
  and SLO guardrails.

## Historical compatibility and version policy

The policy recorded for this release treated V2 as the active compatible product line. Compatible feature tranches used `v2.MINOR.0`, fixes used `v2.MINOR.PATCH`, and `v3.0.0` was reserved for a deliberate materially incompatible product, contract or architecture change with its own migration and acceptance plan. This historical semantic-version policy does not declare current production identity.
