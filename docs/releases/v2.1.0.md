## Delivered contracts

- Gate 0 builds and deploys only the exact approved SHA, with independent
  source verification and manifest-compatible rollback.
- Sales imports use staged generations, manifest/business hash, lease fencing,
  CAS promotion and auditable rollback.
- P&L/TVA uses Decimal, exact `(company, period)` scope and reproducible shadow
  generations; finalized Target and Finance actuals are protected.
- Salary import validates CNP/checksum, both-company manifests, provenance,
  conflict zero-write and transactional rollback.
- Grile reset/recovery is fail-closed; observations are append-only and stale
  refreshes cannot overwrite the current projection.
- Promo/contest configuration and actuals are immutable generations with
  explicit identity policy and pointer CAS.
- Target rules are append-only/effective-dated; new scenarios freeze rule,
  input and profitability snapshots, while legacy remains unversioned.
- Web availability separates the optional ARQ queue from required DB/session
  dependencies and preserves durable terminal state.
- Dashboard has an end-to-end DB deadline and fail-closed per-store forecast
  coverage. PostgreSQL reporting, XLSX spool, Grile phase metrics, Web Vitals
  and PWA upgrade/rollback gates provide the P2 measurement surface.

Additive migrations: `032` through `036`. The frozen baseline and migrations
`001`–`031` are unchanged.

## Explicit limits recorded at release time

- Finance/TVA live promotion was not authorized by this release; it remained
  shadow-only until the pre-image, business hashes and scoped promotion gate
  were approved.
- Salary live mutation was NO-GO until HR reconciled the eight identified
  groups; the release shipped import guards, not a data cleanup.
- P3 refactoring was not accepted yet. Production acceptance required a
  clean 7-day window with at least 100 requests per route, Dashboard/Promo/
  Agent Evaluation p95 targets, zero reads over 3 seconds, and measured
  LCP/INP. A green local or hosted test did not replace that evidence.

## Historical verification route

The release-time closure route required full isolated backend tests, mypy,
frontend typecheck/strict/lint/unit/build, full Playwright, migration
manifest/bootstrap, systemd validation, Gate 0 sandbox and the Grile 10-run
benchmark on one exact commit. Production closure additionally required one
successful manual `CI` run on `main`, formal exact-SHA deploy,
migrations/readiness/public-boundary checks and tag evidence. The current
release/promotion contract is the machine-readable D1-D3 chain described in
[`../README.md`](../README.md).
