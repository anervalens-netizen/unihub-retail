> Post-release correction, 2026-07-17: the release originally rejected both
> duplicate headers and rows. Row equality was later confirmed not to be a
> valid uniqueness rule because the source has no stable line ID and identical
> rows can represent separate units on the same receipt. Duplicate headers
> remain invalid; row multiplicity is preserved under the accepted ADR-004.

## Critical risk remediation

### Import and master-data safety

- A sales file can no longer activate or deactivate stores by omission.
- Store closure/reactivation is a separate CAS-protected, reasoned and audited
  operation tied to the OIDC subject.
- Monetary values, quantities, required identifiers, duplicate headers/rows and
  contradictory store metadata fail before import writes.
- Every snapshot persists a privacy-safe coverage/diff report before promotion.
- Full, 90%, single-company, conflict, duplicate, idempotent retry and concurrent
  same-month cases are covered by isolated PostgreSQL tests.

Migration: `026_import_master_data_safety.sql`
SHA-256: `30063b80755ed86db05cd87c9b130fa632f8ea435df7ddf8c26ce0a38d2999b7`

### Grile check and target synchronization

- `/api/grile/run` and its worker job are strictly read-only.
- Diff and privileged synchronization are separate operations and reservations.
- Sync requires the dedicated OIDC group, CSRF, rate limiting and an audit row
  keyed by stable OIDC `sub`, not email.
- Managed/unmanaged target boundaries and the full target-state hash prevent an
  apparently clean check from hiding mutations.

Migration: `027_grile_target_sync_audit.sql`
SHA-256: `85cfa465351184ded8cd1f0bbae8fe7a084703c92019ea9c7c6093c0d81864d2`

### Salary finalization, archive and reset

- Invalid numeric cells, missing agents/stores, unexpected registry entries,
  Google timeout/429/503 and incomplete coverage fail the operation.
- Partial workbooks and archives never receive or retain the official path.
- Persistent manifests record operation/month, expected and processed coverage,
  control totals, zero-error state, artifact SHA-256, `requested_by_sub`,
  `approved_by_sub` and a verifiable status/hash.
- Archive approval must still be the newest archive attempt when reset starts.
- Live reset requires an approved verified archive, complete source backups and
  per-store checkpoints; rollback is verified and an uncertain checkpoint blocks
  automatic retry.
- Legacy queued jobs fail or normalize safely without treating an email address
  as authorization.

SHA-256: `6bbf34dcb10d923812fb815eb6ef76ae806422f212e893e45bd16fbdb091c2aa`

### Pull-request runner isolation

- PR code runs only on GitHub-hosted `ubuntu-24.04` runners.
- The isolation job proves absence of production paths, the Tailscale interface
  and the production Docker identity/socket. Its direct, no-proxy TimesFM probe
  treats every HTTP response, including 401/403/404, as reachable and fails.
- The former persistent production-host runner was stopped and removed from the
  repository runner inventory.
- Exact private `@unihub/*` packages are vendored and integrity-checked, so CI
  neither assumes access to `127.0.0.1:4873` nor receives a Verdaccio token.
- GitHub actions used by CI/deploy are pinned to commit SHA.
- A successful `main` run produces an immutable source+`dist` archive with source
  SHA and SHA-256 manifest; PR runs never produce a deploy artifact.

## Isolated fixes

- Sensitive API, salary, P&L, photo and export responses receive
  `Cache-Control: private, no-store, max-age=0` plus CDN no-store controls.
- FastAPI docs, Redoc and OpenAPI JSON are disabled in production code.
- SPA fallback is limited to GET/HEAD HTML navigations outside server/API/auth
  namespaces and never masks missing assets.
- Target Calculator validates the complete batch before any row/revision write;
  one invalid code leaves the transaction unchanged.
- Session refresh uses token-owned compare-delete locks, a bounded owner window
  below the lease, bounded waiters and ciphertext compare-delete so concurrent
  requests cannot delete a successfully rotated session.
- Closed plans, duplicate audit notes and historical Markdown archives were
  removed from `HEAD` while remaining recoverable from Git history. Canonical
  documentation was reconciled, two unused forecast experiment wrappers were
  removed, and repository hygiene now prevents a new `docs/archive/` tree.

The Retail reverse-proxy stanza returns 404 for `/metrics`, `/docs`, `/redoc`
and `/openapi.json`, while local liveness/readiness remain healthy. No global
proxy, Authentik, DNS, Astra or Dell configuration was changed for this release.

had only the reviewed single-command sudo boundary. A manual deployment was not
an accepted substitute.
